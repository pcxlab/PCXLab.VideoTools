# Investigation Report

## Purpose

This template is used to document investigations into unexpected behaviour, production issues, test failures, performance concerns, or architectural questions.

Its purpose is to capture facts, analysis, conclusions, and recommendations so future developers and AI assistants do not need to repeat the same investigation.

# Background

Describe what triggered the investigation.

Examples:

- Production issue
- Failed test
- Unexpected behaviour
- Customer report
- Performance concern

---

# Scope

Clearly define what is included in this investigation.

Also describe what is intentionally outside the scope.

---

# Observations

Record only objective observations.

Examples:

- Error messages
- Log output
- Test results
- Production behaviour
- Measured timings
- Screenshots
- File comparisons

Do not draw conclusions in this section.

---

# Investigation Process

Describe the steps taken.

Examples:

1. Reproduced the issue.
2. Reviewed affected architecture.
3. Examined relevant source code.
4. Executed targeted tests.
5. Compared production behaviour.
6. Validated assumptions.

---

# Findings

Summarize the confirmed findings.

Clearly distinguish between:

- Confirmed facts
- Probable causes
- Remaining uncertainties

Avoid speculation.

---

# Root Cause

If identified, describe the confirmed root cause.

If no root cause has been confirmed, explain why.

---

# Resolution

Describe the implemented solution, if applicable.

If no implementation was performed, describe the recommended next steps.

---

# Validation

Describe how the findings or solution were validated.

Examples:

- Unit tests
- Regression tests
- Production recordings
- Manual verification
- Code review

---

# Risks

Identify any remaining risks or unknowns.

Include recommendations for future monitoring if appropriate.

---

# Related Files

List the key files involved in the investigation.

Examples:

- Source files
- Test files
- Documentation
- Production artifacts

---

# Recommendations

List any recommended follow-up work.

Examples:

- Additional testing
- Refactoring
- Documentation updates
- Performance improvements
- Architectural review

---

# AI Context

This investigation should allow a future AI assistant to answer:

- What was investigated?
- Why was it investigated?
- What was discovered?
- Was the issue resolved?
- What work remains?

without repeating the investigation.

---

# Update Rules

Investigations should record what was known at the time.

Do not rewrite historical investigations.

If new evidence changes the understanding, create a follow-up investigation or update the status while preserving the original findings.
